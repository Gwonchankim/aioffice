# Orion Console 제품 요구사항 문서(PRD)

> 문서 버전: 1.0  
> 작성일: 2026-07-20  
> 상태: 구현 기준선(Baseline)  
> 대상 제품: Codex CLI와 Claude Code CLI를 통합한 로컬 멀티에이전트 운영 콘솔

## 1. 문서 목적

이 문서는 Orion Console의 제품 목표, 사용자, 범위, 핵심 기능, 성공 기준 및 출시 조건을 정의한다. 개발·디자인·QA 에이전트와 사람이 동일한 목표를 공유하도록 하는 제품 수준의 기준 문서이며, 세부 구현 방법은 `orion-console-technical-specification.md`에서 정의한다.

## 2. 제품 개요

Orion Console은 사용자의 Windows PC에 설치된 Codex CLI와 Claude Code CLI를 실행 엔진으로 사용해 여러 전문 AI 에이전트를 구성·호출·관찰·검증하는 로컬 웹 애플리케이션이다.

사용자는 자연어로 목표와 성공 조건을 입력한다. 전체 총괄 에이전트 Orion은 목표를 작업 그래프로 분해하고, 서버의 규칙 엔진은 권한·자료 등급·비용·동시성·의존성을 검증한다. 승인된 작업은 역할별 에이전트에 자동 배정되며, 결과는 테스트와 리뷰를 거쳐 하나의 최종 산출물로 통합된다.

제품의 본질은 터미널 로그를 보여주는 단순 뷰어가 아니라 다음 기능을 가진 **로컬 AI 에이전트 제어 평면(Control Plane)** 이다.

- 두 CLI 공급자의 실행과 세션을 하나의 방식으로 관리한다.
- 18개 전문 에이전트의 역할·SOUL·모델·권한을 관리한다.
- 계획, 실행, 검증, 통합, 승인, 기록 보존을 일관된 워크플로로 제공한다.
- Git 프로젝트의 사용자 작업 폴더를 보호하면서 에이전트별 독립 worktree에서 변경한다.
- 외부 변경은 반드시 사람 승인을 거친다.

## 3. 배경과 해결하려는 문제

### 3.1 현재 문제

개별 AI CLI를 각각 사용하면 다음 문제가 발생한다.

- 어떤 에이전트가 어떤 역할과 모델로 작업했는지 추적하기 어렵다.
- 여러 CLI 세션의 상태, 로그, 산출물, 비용을 한눈에 보기 어렵다.
- 병렬 에이전트가 같은 파일을 수정하면 충돌하거나 사용자 변경을 손상시킬 수 있다.
- 모델이 만든 계획을 그대로 실행하면 권한 초과, 무한 재시도, 불필요한 비용이 발생할 수 있다.
- 코딩, 경영, 재무, 소재과학, 규제 검토 결과를 하나의 의사결정으로 통합하기 어렵다.
- push, PR, 배포, 외부 메시지처럼 되돌리기 어려운 작업에 일관된 승인 절차가 없다.

### 3.2 제품 기회

Codex CLI와 Claude Code CLI는 비대화형 실행, JSON 스트리밍, 세션 재개, 모델 선택 및 권한 제어를 제공한다. 이를 공통 실행 계층으로 추상화하면 공급자별 장점을 유지하면서도 하나의 작업 큐·권한 체계·검증 체계로 운영할 수 있다.

## 4. 제품 비전과 최종 목표

### 4.1 제품 비전

“한 사람이 여러 전문 AI 에이전트로 구성된 회사를 안전하게 운영할 수 있는 로컬 제어실”을 만든다.

### 4.2 최종 목표

1. 사용자가 목표만 입력하면 Orion이 적절한 전문 에이전트를 선택하고 작업 순서를 설계한다.
2. 최대 18개 역할 중 필요한 에이전트가 자동으로 협업하며 최대 8개가 병렬 실행된다.
3. 코딩 작업은 독립 worktree에서 구현·테스트·리뷰·통합까지 자동 완료된다.
4. 경영·재무·과학기술·규제 작업은 근거와 리스크가 포함된 의사결정 문서로 통합된다.
5. 모든 실행은 프로필 버전, 모델, 프롬프트, 로그, 변경, 테스트, 승인 및 결과까지 추적된다.
6. 사용자는 언제든 중지·재시도·승인·거절·모델 변경·프로필 변경을 할 수 있다.
7. 핵심 제어 시스템이 안정된 뒤 2D 가상 오피스를 동일한 실시간 이벤트 위에 구현한다.

## 6. 사용자와 주요 사용 사례

### 6.1 1차 사용자

한미르 내부의 의사결정자이자 로컬 개발·연구 프로젝트를 직접 관리하는 단일 사용자다. 사용자는 기술적인 세부사항을 확인할 수 있지만, 모든 에이전트 작업을 터미널에서 직접 조정할 필요는 없어야 한다.

### 6.2 주요 사용 사례

#### 경영·기술 의사결정

- 신규 기능성 코팅 사업의 시장성, 기술성, 재무성, 규제 리스크를 동시에 검토한다.
- Atlas, Miro, Aegis, Helios, Ledger, Regula의 결과를 Orion이 하나의 권고안으로 통합한다.

#### 소프트웨어 개발

- 제품 요구사항을 Nexus가 정리하고 Archon이 아키텍처를 설계한다.
- Forge, Luma, Iris, Keystone이 격리된 브랜치에서 구현한다.
- Verify와 Sentinel이 기능·성능·보안 품질을 검증한다.
- Archon이 통합하고 Orion이 최종 결과를 보고한다.

#### 장애 분석과 수정

- 로그와 재현 정보를 입력하면 Archon, Keystone, Sentinel이 원인을 분석한다.
- 담당 개발 에이전트가 수정하고 Verify가 회귀 테스트를 수행한다.

#### 문서·분석 업무

- 재무자료, 시험 결과, 시장 문서를 분석해 근거·가정·리스크가 분리된 보고서를 생성한다.

## 8. 제품 범위

### 8.1 v1 필수 기능

#### 프로젝트 관리

- 로컬 Git 저장소 등록·해제
- 저장소 경로, 기준 브랜치, 자료 등급, 허용 명령, 기본 예산 설정
- Git 상태·CLI 접근·기준 브랜치 검증
- 사용자 작업 폴더를 변경하지 않는 격리 worktree 관리

#### 에이전트 관리

- 18개 기본 프로필 제공
- Description, SOUL.MD, 모델, 추론 강도, 권한, 대체 모델 편집
- 프로필 변경 이력과 실행별 스냅샷 보존
- JSON/YAML 가져오기·내보내기
- 모델 및 CLI 가용성 상태 표시

#### 과제 관리

- 자연어 목표, 성공 기준, 입력 파일, 프로젝트, 실행 한도 입력
- Orion 계획 생성 및 DAG 시각화
- 계획 검증, 시작, 일시중지, 취소, 재시도
- 단계별 담당 에이전트·의존성·산출물·검증 기준 표시
- 전체 상태와 단계별 상태 실시간 갱신

#### 자동 실행과 모델 라우팅

- Codex와 Claude CLI 비대화형 실행
- 최대 8개 병렬 실행과 공급자별 rate limit 대응
- 세션 재개, 타임아웃, 취소, 단계별 재시도
- 모델 불가 시 대체 모델 자동 선택
- 실제 사용 모델과 변경 이유 기록

#### 변경·검증·통합

- 수정 에이전트별 독립 worktree와 브랜치 생성
- 로컬 커밋과 변경 요약 생성
- 테스트 명령 실행과 결과 수집
- Verify·Sentinel 품질 게이트
- Archon 통합 브랜치와 충돌 해결 시도
- 실패 시 잔여 변경을 보존하고 사용자에게 에스컬레이션

#### 승인 센터

- push, PR, 배포, 외부 메시지 등 외부 변경의 승인 요청
- 대상, 실행 내용, 영향, 롤백 가능성, 만료시간 표시
- 승인·거절·수정 요청 기록
- 승인되지 않은 외부 변경 차단

#### 대시보드와 관측성

- 프로젝트·과제·에이전트·승인·산출물 중심 화면
- 실행 중 에이전트, 모델, 경과시간, 단계, 실시간 로그 표시
- 작업 DAG와 의존성 표시
- 테스트 결과, 커밋, 파일 변경, 보고서 다운로드
- 토큰·호출 횟수·실행시간 표시
- 구독 실행에서 비용이 확인되지 않으면 금액을 임의 추정하지 않음

#### 데이터와 보안

- `127.0.0.1` 전용 바인딩
- 임시 로컬 세션과 Origin 검증
- CLI 로그인 토큰 미저장
- 자료 등급에 따른 공급자·모델 제한
- 90일 자동 보존 및 즉시 삭제
- 민감정보 로그 마스킹

### 8.2 v1 이후 기능

- Windows 설치 앱 또는 서비스 패키징
- 사내 LAN·VPN 접속과 다중 사용자 권한
- 원격 샌드박스 및 클라우드 실행
- 예약 작업, 알림, 이메일·Slack·GitHub 커넥터
- 조직 단위 비용·정책 대시보드
- 2D 가상 오피스와 아바타 상태 시각화
#### Arca 내부 지식 레지스트리(M1-M5 계약)
- M1-M5에서 18번째 에이전트 Arca는 권한 있는 사용자와 에이전트가 권위 있는 원문을 찾도록 자료의 위치·권한·버전·최신성과 승인된 최소 요약을 관리한다.
- 이 계약은 중복 조사를 줄이고, 기존 source store가 보유하는 원문·민감 원본을 AI memory에 저장하지 않는 경계를 제공한다. Arca는 metadata card와 승인된 최소 요약만 보관하며 기존 source store의 원문은 불변으로 유지한다.
- M0에서 Arca는 문서·명세 계약일 뿐이며 registry, DB/FTS5, connector, search, profile seed·실행, scheduler, audit 또는 source repository 접근·변경을 제공하지 않는다. M0 health는 Arca, database, scheduler, retention을 운영 상태로 표시하지 않는다.


### 8.3 명시적 제외 범위

- v1에서 3D 메타버스, 음성 채팅, 키보드 아바타 이동은 구현하지 않는다.
- v1은 통제 등급 자료를 원격 LLM으로 처리하지 않는다.
- 사용자 승인 없이 원격 저장소·배포 환경·외부 서비스 상태를 변경하지 않는다.
- 모델 공급자의 결제·구독·계정을 앱이 대신 관리하지 않는다.
- 에이전트가 독자적으로 법률·세무·규제 최종 결정을 내리게 하지 않는다.

## 10. 비기능 요구사항

### 성능

- 일반 API의 로컬 응답 p95는 실행 스트리밍을 제외하고 300ms 이내다.
- 8개 에이전트가 동시에 이벤트를 보내도 UI 입력과 화면 이동이 멈추지 않는다.
- 로그 100,000건이 있는 과제도 가상화 목록으로 열 수 있다.
- 서버는 메모리 사용률 80% 초과 또는 가용 메모리 2GB 미만에서 새 실행을 지연한다.

### 신뢰성

- 상태 변경과 이벤트 저장은 중복 실행에 안전해야 한다.
- 서버 종료 후 재시작했을 때 실행 중이던 프로세스를 ‘중단됨’으로 식별하고 재개 가능 여부를 표시한다.
- 앱이 만든 worktree와 커밋은 자동 실패 후에도 손실되지 않는다.
- 모델 대체와 재시도는 최대 횟수를 넘지 않는다.

### 보안

- 서버는 외부 인터페이스에 바인딩하지 않는다.
- 웹 요청의 Origin, 세션, 경로를 검증한다.
- CLI는 셸 문자열이 아니라 실행 파일과 인자 배열로 호출한다.
- 위험한 CLI 권한 우회 플래그를 사용하지 않는다.
- 등록되지 않은 경로와 앱 관리 범위 밖의 worktree는 삭제하지 않는다.
- 통제 등급 프로젝트는 원격 모델 실행을 차단한다.

### 사용성

- 핵심 상태는 색상만이 아니라 텍스트와 아이콘으로도 구분한다.
- 실패 화면은 원인, 영향, 자동 조치, 다음 사용자 행동을 보여준다.
- 기술 로그와 경영 요약을 분리해 제공한다.
- 한국어 UI를 기본으로 하고 원문 CLI 오류는 접어서 확인할 수 있다.

### 유지보수성

- 공급자별 구현은 공통 어댑터 인터페이스 뒤에 격리한다.
- API와 이벤트는 Zod 스키마에서 타입과 런타임 검증을 함께 생성한다.
- 에이전트 프로필 변경은 애플리케이션 배포 없이 가능해야 한다.
- 핵심 오케스트레이션은 UI와 분리해 테스트 가능해야 한다.

## 11. 성공 지표

### 제품 성공 지표

- 등록 프로젝트에서 첫 멀티에이전트 과제를 10분 이내에 생성·시작할 수 있다.
- 사용자가 터미널을 직접 열지 않고 과제 생성부터 결과 검토까지 완료할 수 있다.
- 코딩 인수 시나리오와 경영·과학기술 인수 시나리오를 각각 3회 연속 성공한다.

### 운영 지표

- 중복 단계 실행률 0%

- 모델 불가 상황에서 자동 대체 성공률 90% 이상
- 서버 재시작 후 작업 기록 복구율 100%

### 품질 지표

- 핵심 도메인·정책·어댑터 코드 라인 커버리지 80% 이상

- 출시 시 Critical/High 보안 결함 0건
- 접근성 자동 검사에서 Critical 위반 0건

## 14. 완료 정의

v1은 다음 조건을 모두 만족할 때 완료로 본다.

- P0 기능 요구사항이 모두 구현되고 자동 테스트가 통과한다.
- 두 CLI의 로그인 상태와 실제 smoke test가 확인된다.
- 18개 프로필이 웹에서 조회·수정·실행 가능하다.
- 코딩 작업이 계획부터 로컬 통합 커밋까지 자동 완료된다.
- 비코딩 작업이 근거와 리스크를 포함한 최종 보고서로 통합된다.
- push·PR·배포는 승인 없이는 실행할 수 없다.
- 사용자 기준 저장소와 기존 변경이 손상되지 않는다.
- 자료 등급, 90일 보존, 모델 대체, 서버 재시작 복구가 검증된다.
- 알려진 Critical/High 보안 결함과 P0 버그가 없다.
