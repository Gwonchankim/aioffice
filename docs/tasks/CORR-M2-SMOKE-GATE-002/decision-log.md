# CORR-M2-SMOKE-GATE-002 — Decision Log

- **WORKFLOW_MODE = controller_isolated.** P2 review and P4 validation ran in distinct isolated worker contexts with recorded worker IDs (see worker-registry.md).
- **Grant is the sole argv model source (SMG-001).** The run never re-reads the model env as the argv source; a differing run-time model env is a hard 0-spawn `MODEL_BINDING_CONFLICT`. Rationale: prevent a grant/run model divergence after authorization.
- **Executable bound by content fingerprint, re-checked just-in-time (SMG-002 / RB4).** The grant persists a SHA-256 content fingerprint + cliVersion + basename per provider (grant-time `--version` probe, 0 model call). The run re-resolves + re-fingerprints each executable immediately before ITS OWN spawn to close the sequential replacement window. Only the fingerprint hash (never a raw path) appears in evidence.
- **Policy projection bound + re-projected (RB1).** argv-policy version, result-schema hash, prompt hash, and repository-template version are bound in the grant and recomputed/compared at run (`POLICY_BINDING_MISMATCH` ⇒ 0 spawn), defending against code/data drift between grant and run.
- **Strict grant schema with EXACT fixed options (SMG-003 / RB7 / DB).** Unknown keys at any nesting level, wrong `maxInvocations`, and non-exact `timeoutMs`/`maxBudgetUsd` (compared to the live constants) fail closed — in-range tampers (299999, 0.25) are rejected.
- **One envelope on every path; injectable seams (SMG-004 / RB5).** `runProviderSmoke`, `runDeferredProviderSmoke(overrides)`, and `runSmokeCli(argv, deps)` guarantee a single `{schemaVersion,providers[],cleanup}` (run) or sanitized grant envelope; never `[]`, never a raw exception. Partial provider evidence is preserved (monotonic accumulator, RB2).
- **Per-run ResourceTracker owns cleanup above preparation (SMG-005 / RB3).** Temp dirs are tracked immediately after allocation and cleaned in a `finally`, so a mid-preparation throw still cleans; only tracked run dirs are removed; `cleanup:'incomplete'` is a non-pass (RB9).
- **Repository-mutation halt (SMG-006).** Any repository change halts the remaining provider (`security_halt`, 0 spawn, reserved slot fail-closed); an unknown/throwing snapshot is treated as changed (fail-closed). A non-mutating provider failure does not by itself halt the other provider.
- **Spawn-attempt marker distinct from reservation (SMG-007).** `.spawn` markers (atomic `wx`, written before the real spawn, crash-durable) back `spawnAttemptCount`; `invocationCount` is defined as the cumulative spawn-attempt count; a monotonic in-memory lower bound prevents under-reporting when a ledger recount fails.
- **Only installed-CLI-supported isolation flags (SMG-008).** Probed read-only against the installed CLIs: codex 0.145.0 gains `--ephemeral/--ignore-user-config/--ignore-rules`; claude 2.1.156 gains `--no-chrome/--no-session-persistence/--strict-mcp-config/--mcp-config {}/--disable-slash-commands`. `--max-turns` is NOT supported by claude 2.1.156 and is deliberately omitted (recorded); no auto fallback. `--print` is single-turn and `--max-budget-usd 0.50` bounds cost.
- **Grant CLI emits only a one-way `authorizationIdHash` (RB6 / DA).** The raw authorization id and any raw path are never emitted; the operator confirms by hashing their own id.
- **SMG-009 evidence correction is additive.** `gpt-5.6-sol` is NOT re-asserted invalid; its per-account/CLI availability is recorded UNVERIFIED (verifying requires a prohibited real call). The correct removal rationale (authorization-binding, unverified availability, no auto-change on failure) is recorded without deleting prior evidence. Validated product SHA and final evidence HEAD are distinguished.
- **Dependency remediation for the SMG-010 audit gate.** The initial P4 found a pre-existing, newly-disclosed transitive High advisory (GHSA-c96f-x56v-gq3h, `find-my-way <=9.6.0` via `fastify`). Because SMG-010 mandates `pnpm audit` Critical 0 / High 0 as a required deliverable, a minimal, security-positive, dependency-only pnpm override (`find-my-way@<9.6.1` → `>=9.6.1`, resolving to 9.7.0) was added to `pnpm-workspace.yaml`; no product code changed; the full gate set + all fastify server suites re-validated green. This was disclosed, not hidden; it is orthogonal to the smoke-gate code.
